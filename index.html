叙事主线

一次生成的 deck 改不动；把 deck 当成可维护的源文件，人和 Agent 都能改、能回滚、能审阅。先讲为什么，再讲方法，然后讲工具，最后给出开始的方法。

以图为主，不连续放纯文字页；示意与真实分开；方法和工具的每个说法，都来自一次真实的汇报 deck 制作过程。

01

为什么：难在第五轮修改

汇报材料要改十几轮：主次、数据口径、措辞、受众都会变。手做慢，一次性生成改不动。

讲述重点

用三种做法对比，引出“deck 是可以反复审的叙事”这一主张。

02

方法：先定讲什么，再排每一页

资料进仓库 → 叙事主线 → 逐页大纲 → 页面 → 角色审阅 → 修订留痕；六条原则；三种图的分工；截图自检。

讲述重点

重点讲角色审阅：子 Agent 扮演听众挑毛病，问题与处理进版本记录。

03

工具：一个网页工作台

deck.py 生成网页与 JSON；网页编辑回写 JSON；默认值跟踪；叙事与大纲工作区；组件库；播放与导出；无头自检。

讲述重点

每个功能配工作台自己的截图。
